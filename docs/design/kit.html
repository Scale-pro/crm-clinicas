Kit de mockup — CRM Clínicas docs/design/kit.html

Como usar este arquivo

Este arquivo é a base para mockups de tela do CRM Clínicas. Todo mockup feito a partir dele usa apenas:

  • os tokens declarados em src/app/globals.css (as variáveis CSS copiadas na seção 1 do <style>);
  • as réplicas dos componentes que já existem em src/shared/ui/ e no shell de src/app/(clinic)/app/, reproduzidas abaixo.

Qualquer coisa fora disso é pedido de componente novo — não é mockup. Cor literal (#hex, rgb(), um oklch() que não esteja nesta lista), espaçamento ou raio fora das escalas usadas aqui, ícone que não seja lucide, ou um bloco visual que nenhum componente existente produz: tudo isso vira, explicitamente, uma proposta de novo componente ou de novo token — a ser discutida e aprovada antes de virar código, conforme a ADR-011.

Se um mockup não consegue ser montado só com o que está aqui, isso é um achado — registre a lacuna em vez de aproximar com CSS solto. Ver também a seção Registro de divergências e lacunas.

Acessibilidade não é opcional no mockup: cor nunca é o único portador de informação, todo campo tem rótulo real vinculado, e todo estado (vazio, erro, carregando, sem acesso) tem texto. Os componentes abaixo já vêm com esses papéis ARIA — mantenha-os ao copiar.

5. Drawer — o painel lateral do projeto src/shared/ui/drawer.tsx

Não existe um componente chamado SidePanel em src/shared/ui/. O painel lateral do projeto é o Drawer, replicado aqui. Ele é um <dialog> nativo aberto com showModal(): o navegador cuida do foco preso, da pilha de camadas e do Escape; o gatilho recupera o foco ao fechar. Se o pedido de mockup for por um painel não modal (ancorado, sem backdrop, conteúdo da página ainda operável), isso é um componente novo, não o Drawer.

12. Registro de divergências e lacunas

O que não deu para replicar fielmente em HTML puro, e o que foi pedido mas não existe no código. Nada aqui foi “aproximado”: está registrado para ser resolvido no lugar certo.

Pedido no briefing, inexistente no código

  • SidePanel não existe. Não há nenhum arquivo com esse nome em src/shared/ui/. O painel lateral do projeto é o Drawer (src/shared/ui/drawer.tsx), replicado na seção 5. Se o mockup precisar de um painel lateral não modal, isso é um componente novo — precisa ser proposto, não improvisado.
  • MetricCard não é de shared/ui. Ele vive em src/app/(clinic)/app/_dashboard/metric-card.tsx, junto com MetricGrid. Reusá-lo fora do dashboard exige promovê-lo a shared/ui primeiro (ADR-003: módulos só se falam pela interface pública).

Replicado visualmente, mas com comportamento simplificado

  • Tabs — o componente React mantém foco itinerante com roving tabindex, setas, Home/End, e monta apenas o painel ativo. Aqui os quatro painéis existem no DOM (os inativos com hidden) e o JS de demonstração cobre clique e setas. Semântica ARIA e aparência são fiéis; a montagem condicional não é.
  • Drawer — usa <dialog> + showModal(), igual ao componente, então foco preso, camada e Escape são reais. A devolução de foco ao gatilho está no script; o gerenciamento por useRef/ useEffect do React não tem equivalente aqui.
  • FilterPopover — abertura, Escape e clique fora estão no script. No componente, os campos permanecem montados dentro do form method="get" que o envolve; no mockup, mantenha-os dentro de um <form> para não perder essa característica.
  • SidebarNav — o estado ativo vem de usePathname(). Aqui o item ativo é marcado à mão com aria-current="page". Em mockup, marque sempre o item da tela que está sendo desenhada.
  • AppHeader — o rótulo da seção é derivado da rota por uma tabela em _shell/app-header.tsx. Aqui é texto fixo; use um dos rótulos já existentes naquela tabela em vez de inventar um novo.
  • Ícones — são os SVGs do lucide-react usados no projeto, colados inline (mesmos path, viewBox 24, stroke-width 2). Só use ícones que existam no lucide.
  • Navegação mobile — _shell/mobile-navigation.tsx coloca a mesma sidebar dentro de um Drawer com side="left". O botão do header abre uma versão reduzida desse drawer aqui; a instância dupla (desktop + mobile, com prefixos de ID distintos) não é reproduzida.

Existe em src/shared/ui/, fora do escopo deste arquivo

Não estão replicados aqui, mas existem — se o mockup precisar de um deles, o componente já está pronto no código e deve ser lido lá antes de ser desenhado (e, de preferência, acrescentado a este kit):

actions-menu, clinic-selector, color-indicator, confirm-dialog, controlled-field, duration-input, error-summary, feedback-banner, loading-table, money-input, stage-accent, submit-button, support-mode-banner.

Replicados por serem necessários às seções acima, mesmo sem estarem no briefing: skeleton (base do LoadingState), input (controle do FormField) e page-toolbar (barra da área de conteúdo).
